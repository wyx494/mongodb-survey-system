# 基于 MongoDB 的在线问卷系统

课程大作业。第一阶段是一个简化版的在线问卷系统：注册用户可以创建问卷、通过短链分发、收集答卷，并按题目自动统计结果。第二阶段加入题目库：题目成为独立资源，支持版本、共享、引用反查和跨问卷统计。

技术栈：Node.js 22 + Express + MongoDB 8（官方 `mongodb` 驱动，不使用 Mongoose）+ EJS。

## 功能

- 账号：注册、登录、退出；密码加盐哈希；登录后只能看到自己的问卷
- 问卷：创建、编辑题目、发布、关闭、设置截止时间、复制短链
- 题型：单选、多选（可限制最少/最多/必须选几个）、填空（文本长度）、数字（范围、是否整数）
- 跳转：按单选/多选/数字的结果跳题，规则存在问卷里，可在编辑页配置
- 填写：登录后逐题作答、按规则跳转、前后端双重校验、匿名/记名、可限制重复填写
- 统计：单选计数、多选计数、填空列表、数字平均值/最值，整卷与单题统计
- 题库（第二阶段）：问卷里创建的题目自动进入题库，可重复使用
- 版本：修改题目生成新版本；已发布问卷引用旧版本，不受影响；可查看历史、恢复旧版
- 共享：题目可共享给其他用户，被共享人可以使用，但不能修改原题
- 引用反查：查看一道题被哪些问卷使用
- 跨问卷统计：按题目汇总所有问卷的回答，不同版本分开显示

```

├─ server.js              启动入口
├─ src/
│  ├─ app.js              Express 应用组装
│  ├─ config.js           配置（端口、数据库、会话时长）
│  ├─ db.js               连接、集合校验器、索引
│  ├─ auth.js             密码哈希、会话、登录中间件
│  ├─ routes/             auth / surveys / public / stats / questions / pages
│  ├─ services/           jump、validate、stats、survey、questions（题库与版本）、migrate
│  └─ views/              EJS 页面
```

仓库里放代码、测试、这份 README 和 AI 使用日志；数据库设计、API 说明、测试用例和项目报告随作业单独提交。

## 快速开始

### 0. 准备 MongoDB

本机已安装 MongoDB 8.3，但安装时没有完成初始化（没有注册服务，也没有数据目录）。可以先手动启动：

```bat
mkdir "%LOCALAPPDATA%\MongoDB\data"
"C:\Program Files\MongoDB\Server\8.3\bin\mongod.exe" --dbpath "%LOCALAPPDATA%\MongoDB\data" --bind_ip 127.0.0.1 --port 27017
```

也可以直接运行 `scripts\start-mongo.bat`。

### 1. 安装依赖

```bat
npm install
```

### 2. 初始化数据库（建集合、索引、校验器）

```bat
npm run init-db
```

如果数据库里已经有第一阶段的问卷（内嵌题目），再执行一次迁移：

```bat
npm run migrate-v2
```

迁移会把内嵌题目变成“题目 + v1”，并给历史答卷补上题目引用。`npm run seed` 会自动执行迁移。

### 3.（可选）写入演示数据

```bat
npm run seed
```

会创建演示账号 `demo / demo123`、一份已发布的“课程学习体验调查”（含 5 份答卷）和一份草稿问卷。

### 4. 启动

```bat
npm start
```

打开 <http://localhost:3000>。

### 5. 跑测试

```bat
npm test
```

自动化测试使用独立的数据库（`survey_test_*`），跑完会删掉，不影响演示数据。

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 服务端口 |
| `MONGODB_URI` | `mongodb://127.0.0.1:27017` | MongoDB 连接串 |
| `DB_NAME` | `survey_system` | 数据库名 |
| `SESSION_TTL_DAYS` | `7` | 会话有效期（天） |

## 设计上的几个约定

1. **匿名 ≠ 免登录**：按需求，填写者仍然要登录；匿名只是答卷里不保存填写人。
2. **发布后题目锁定**：避免已收到的答卷和题目对不上；标题、说明、截止时间仍可改。
3. **跳转只能向后**：发布前会校验目标题存在且排在当前题之后，避免死循环。
4. **服务端为准**：填写页在前端也会算一遍跳转（为了即时反馈），但提交时服务端会从第一题重新走一遍路径并校验。
5. **引用 + 快照**：问卷里保存题目的 `questionId`/`version`，同时保留一份内容快照。这样已发布问卷不会因为题库改版而变化，读取时也不用联表。
6. **版本只增不改**：修改题目生成新版本；恢复旧版也是“用旧内容生成新版本”，历史记录不会被覆盖。
7. **跨版本统计分开看**：同一道题的不同版本选项可能不同，统计页按版本分开显示，不做强行合并。

## 已知限制

- 界面是课程作业级别的简单页面，没有做响应式的精细打磨。
- 没有做 CSRF token、限流、验证码。
- 题库目前只有“个人 + 指定共享”，没有做公开题库、题目分类和搜索。
- 跨问卷统计按版本分开显示；如果两个版本的选项 key 完全不同，不做语义合并。
